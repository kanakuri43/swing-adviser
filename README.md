# swing-adviser

日本株スイングトレード（保有2週間〜1カ月、日足）の判断支援用・個人向け Windows デスクトップアプリ。仕様と設計方針は `CLAUDE.md`、実装の記録は `TODO.md` / `tasks/todo.md` を参照。

## バックテスト完了後の進め方

バックテスト（`tools/SwingAdviser.Backtest`）は一通り完了した。結果は `tasks/todo.md` の「レビュー」に記録済み。要点は次のとおり。

- 現行の仮値では優位性はほぼ無い（全体の平均R +0.016）。Long だけが小さくプラス（+0.10R。生存バイアスで実際はもっと小さい可能性が高い）。
- Short は前半・後半ともマイナスだったため、候補を既定で出さないようにした（`Gates.ShortCandidatesEnabled=false`）。
- スコア配点や細かいパラメータの差はノイズの範囲で、成績を区別できていない。

次にやる順番は以下。

1. **今の運用を数週間〜数カ月続ける（実装不要）**
   - 約定は必ずアプリに入力する。実際の約定がたまらないと次の検証材料が増えない。
   - バックテストには、寄付の価格や逆指値の約定、判断のばらつきなど実運用の要素が入っていない。
2. **決算またぎの警告**
   - 損切に当たるのは34%で、平均 −1.05R。−1 を超える分はギャップ（決算発表の翌日などに起きやすい）。
   - 先に確認: `trades.csv` に決算日を重ねて、決算またぎの平均Rが悪いかを確かめる（決算日のデータは手元に無いので、入手方法から決める）。
   - 効果が確認できたら、AI評価の出力に「次回決算予定日」を足し、保有期間内なら警告する。
3. **翌朝の見送りラインの表示**
   - 例:「寄付が 終値＋0.5ATR を超えたら見送り」の目安。発注はしないのでルールに反しない。
   - 先に確認: `trades.csv` で、シグナル翌日の始値がギャップアップしたトレードとそうでないトレードの平均Rを比べる（既存データだけで可能。最初に着手できる）。
   - 差が無ければ作らない。
4. **候補の追跡集計は優先度を下げる**
   - バックテストが数年分を先に出したので、数週間待つ必要はなくなった。
   - やるなら、実際の約定の平均Rとバックテストの平均Rを数カ月分並べる程度で足りる（新しい仕組みは作らない）。

### やらないこと
- スコア配点や細かいパラメータの調整（差がノイズの範囲だった）。
- 指標の追加（`CLAUDE.md` の「4指標のみ」に反する）。
- 案を大量に増やして勝ちパターンを探すこと（偶然の当たりを拾う過剰最適化になる）。試すなら理由のある数案に絞り、前半で選んで後半で1回だけ確認する。

## バックテストの使い方

定期的に回す必要は無い。設定値や候補条件を変えたいときと、半年〜1年に1回の見直しで十分。

```powershell
# データ取得（約13分。キャッシュは backtest-cache/、更新は --refresh）
dotnet run --project tools/SwingAdviser.Backtest -c Release -- fetch

# 実行（約1.5分。別設定で比べるときは --settings と --out を変える）
dotnet run --project tools/SwingAdviser.Backtest -c Release -- run --out backtest-output/baseline
```

- 半年〜1年ごとの確認は、Long の平均Rが前半・後半と同程度でプラスを保っているかを見るだけでよい。
- 母集団は現在の上場銘柄なので上場廃止銘柄が無く、Long が良く見えやすい。結果は割り引いて読む。
